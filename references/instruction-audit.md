# 指令审计

在删减草稿或诊断膨胀的 Skill 时阅读此文件。

## 证据门槛

每条指令必须给出一个理由：

1. 一项不可推断的事实或不变量；
2. 一条硬政策、安全或范围边界；
3. 一份输出契约或可检查的完成条件；
4. 一个指令所防止的已复现失败。

以上都不满足则删除。

## 必须保留

- 将本 Skill 与相邻 Skill 区分开的调用条件。
- Agent 无法从文件、工具或当前请求中推断的事实。
- 不可逆操作、安全、法律和范围边界。
- 必需的产出物形态和可检查的成功标准。
- 经代表性案例证明必要的最小决策规则。

## 有证据才保留

- 分步编排：仅当顺序是不变量，或评估显示模型会跳过必要依赖时保留。
- 示例：保留能解决已证实歧义的最小示例。
- 例外和回退：仅保留在真实系统边界上可达的情况。
- 强调语气：仅在日常措辞反复失效时保留。

## 默认删除

- 身份陈述和动机性说明。
- 描述合格默认行为的指令。
- 代码、配置、目录结构或命令帮助中已有的权威事实。
- 重述同一分支或规则的近义词。
- 为旧模型添加的、当前无失败案例的变通方案。
- 假设性边界情况、未来扩展、对不可能状态的防御性处理。
- 没有可观察测试的品质形容词，如"好""健壮""彻底"。

## 失败模式

- **No-op**：删掉句子后行为不变。
- **重复**：一个含义有多个存放位置。
- **沉积**：原因消失后仍然保留的曾有用规则。
- **散落**：在不需要的运行中也加载了活跃材料。
- **过早完成**：可见的后续工作将注意力从当前完成条件上拉开。
- **否定式**：禁令激活了不想要的行为，却没有让替代行为变得突出。

## 修复

- No-op → 删除。
- 重复 → 选一处作为唯一事实来源，其余改为指针。
- 沉积 → 复现旧失败；不再发生时删除规则。
- 散落 → 将仅特定分支需要的材料移到精确指针后面。
- 过早完成 → 先锐化完成条件；仅当失败持续时再拆分序列。
- 否定式 → 陈述目标行为；仅当标记硬边界时保留禁令。

## 压缩顺序

1. 删除没有支撑的含义。
2. 删除重复的含义。
3. 用模型已知的领域术语替代重复解释。
4. 将条件性材料移到指针后面。
5. 最后再收紧句子。

不要从缩短句子开始：压缩后的噪音仍然是噪音。

## 结构规范

- 目录结构只用官方认可的名字：`SKILL.md`/`scripts/`/`references/`/`assets/`/`examples/`。自定义名（如 `lib/`、`utils/`）CLI 虽能整体复制，但其他兼容 Agent 可能不认。
- 多 skill 仓库统一 `skills/<name>/SKILL.md`，CLI 递归扫描。放错位置则无法被发现。
- 按需加载的文档放 `references/`，可执行代码放 `scripts/`，平台元数据放 `agents/`。
- 内容拆分的标准是"这条内容是否所有运行都需要"：不是就拆到 `references/` 并配精确指针。
