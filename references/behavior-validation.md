# 行为验证

在创建或实质修改 Skill 后阅读此文件。验证行为，不验证文笔。

## 构建案例集

每类至少一个案例：

1. **正触发** — Skill 必须处理的明确请求。
2. **近邻负触发** — 不应触发本 Skill 的相似请求。
3. **正常路径** — 输入完整的常见任务。
4. **边界路径** — 缺少输入、不可逆操作或硬范围限制。
5. **约束冲突** — 施压让 Agent 违反输出契约或边界的请求。

每次真实失败导致新增指令时，追加一个回归案例。

## 定义观察项

运行案例前记录可观察的预期：

- Skill 是否应被触发；
- 必须执行的操作或产出物；
- 必须保持为真的约束；
- 证明完成的检查；
- 仅在代表硬边界时列出禁止结果。

除非风格是产出物契约的一部分，否则不评估风格。

## 运行案例

对于调用类案例，在 Skill 已安装且 description 可见的会话中测试；手动调用不能测试发现能力。对于执行类案例，每个草案使用相同的模型、工具、项目状态和用户提示词。当一次结果可能隐藏方差时，对随机案例重复运行。

## 对比草案

在同等条件下对基线和精简草案运行相同案例。记录：

| 案例 | 触发 | 任务完成 | 约束保持 | 无关步骤 | 追问次数 | 输入 token |
|---|---|---|---|---|---|---|
| 示例 | 通过/失败 | 通过/失败 | 通过/失败 | 数量 | 数量 | 数量 |

精确计数时使用 Claude token 计数端点。行数或字符数仅为粗略参考。

## 决定

当代表性行为和硬约束没有回退时，接受删除。Token 减少是次要收益。

当行为回退时：

1. 复现失败；
2. 定位缺失的决策或约束；
3. 添加能改变结果的最小、正向、局部的一条指令；
4. 重跑全部案例集；
5. 仅在其回归案例仍然相关时保留该指令。

不要追求硬性的缩减指标。行为无损的小幅缩减，胜过弱化契约的大幅缩减。

## 完成记录

记录：

- 已运行的案例；
- 观察到的失败；
- 删除或恢复的规则及其原因；
- 未解决的不确定性；
- 最终行为和 token 对比。

当全部硬约束通过，且每条保留的指令背后都有不变量或回归案例支撑时，验证完成。
